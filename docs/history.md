# 開発の経緯

## 2026-10-10 デモを作成

- 動機: yoshito.me のページに、発表資料（PDF・PowerPoint）をめくって見られる形で載せたい。
  いきなりサイトに入れず、まずこのディレクトリでデモとして作り、のちに必要なページへ載せる
- デザインは Claude Design で決定（https://claude.ai/artifact/WtzsCj1xr4nXt99H1jDDiM）。
  3案（A: 下に操作バー / B: スライドに重ねる / C: サムネイル列つき）から、
  **普段は A、サムネイルボタンで C の列を開く**形に決めた

### 設計判断

- **PowerPoint はブラウザで表示できないので、手元で PDF に変換してから扱う**。
  Office Online の埋め込みは、ファイルを公開URLで Microsoft に渡す必要があり、限定公開の資料に使えないため不採用
- **表示はすべてページ画像（WebP）にした。PDF.js は使わない**
  - ダウンロード不可の資料を本当に守るには、元の PDF をブラウザに送らないしかない
    （PDF.js でも、暗号化して JS で復号しても、届いた中身はデベロッパーツールから取れる）
  - ダウンロード可の資料は PDF.js で表示する案（文字がくっきり・コピーできる）もあったが、
    表示の仕組みを1つにするため、こちらも画像で表示し PDF はダウンロード用に置くだけにした（ユーザーが選択）
  - その代わり、スライドの文字の選択・コピーはできず、拡大すると PDF より少しぼやける
- **ダウンロード可否の最終判断はサーバーの deck.json**。ページ側の属性だけで決めると、属性を書き換えれば取れてしまうため。
  ページ側はボタンを隠す方向にしか効かない
- 画像はトークン（cookie に結び付けた HMAC、10分）＋ `Sec-Fetch-Dest` の確認＋ `no-store` で返す
- 載せる側のページと干渉しないよう、クラスは `sv-` 始まり・スタイルは `.sv-root` の中だけ・狭い場所の調整はコンテナクエリ
- CSS は JS が自分で読み込む（ページ側は script 1行）。script の `?v=` を CSS にも引き継いで Cloudflare のキャッシュを切り替える

### 未解決（→ 同日、canvas の配置は直した。iPhone 実機での確認は未）

- ヘッドレス Chrome で `--force-device-scale-factor=2` のスマホ幅を撮ると、撮影が終わらなかった。
  canvas の実寸がステージの高さを押し広げ、ResizeObserver → 再描画 → さらに広がる、をくり返している疑いがある
  （対策案: `.sv-canvas` を `position: absolute; inset: 0` にしてステージに重ねる）。
  Retina の Mac の Chrome で目視した範囲では症状は出ていない。yoshito.me に載せる前に、iPhone の実機で確かめる

## 2026-10-10 汎用化して public にする準備

- 動機: 自分のサイト専用にせず、誰でもどこでも使えるようにして公開する（ユーザーの提案）。
  あわせて「ダウンロードボタン以外から取れる経路」を洗い出して塞いだ
- **構成を変えた**: `slide-viewer/` フォルダを配布物そのものにした（js・css・`api/`・`private/`）。
  それまではリポジトリ（`public/`・`server/`・`storage/`）とサイトで構成が違い、書き出し時に sed でパスを書き換えていた。
  デモは `demo/`、デモの資料は `demo/decks/` に移した
- 設定ファイル `private/config.php`（見本は `config.example.php`）。API の場所の既定値を「script と同じ場所の `api/`」にした
- **静的モード**（`data-static`）: PHP の無い場所（GitHub Pages など）でも使えるように。ダウンロード対策は効かない
- ボタンの読み上げ名を日本語と英語に
- ダウンロード対策の追加
  - **マスの並べ替え**: 開発者ツールの「ネットワーク」から保存した画像を、そのままでは使えないようにした。
    漫画の配信サイトと同じやり方。サーバーで要求ごとに並べ替える案は、PHP の負荷と gd の有無に左右されるので、
    登録時に1回だけ並べ替えて保存する形にした
  - **回数制限**（1分間に90枚）。スクリプトでの一括取得を遅くする
  - **印刷でスライドを隠す**
  - 検討してやめたもの: ページごとのトークン。ビューアが全ページ分を受け取る必要があるので、一括取得を防ぐ効果が無い
- 実装中に見つけた不具合: 複数のビューアが同時に cookie を発行すると、最初のトークンが 403 になって取り直す。
  その取り直しの経路でマスを2回並べ替えて（戻して）しまい、表示が崩れた。並べ替えを戻す処理を取り直しの外に出して直した
- 並べ替えた画像を非可逆の WebP（`-q 82`）で保存すると、戻したあとに薄い線や点が残った（圧縮が隣のブロックから予測するため）。
  `-near_lossless 60` にすると跡が消え、大きさもほぼ変わらなかったのでこちらにした（数字は architecture.md）
- README（英語）・README.ja.md・MIT ライセンス・GitHub Pages のデモ（`.github/workflows/pages.yml`）を追加
- 公開にあたり、コミットの作者メールは書き換えないことにした（ユーザーの判断。表に出すアドレスとして使っている）

## 2026-10-10 public にする前のセキュリティの見直し

- ページ数の表示で deck.json の値を HTML として入れていた（`innerHTML`）。静的モードで deck.json が書き換えられると
  スクリプトを実行されうるので、文字として入れるようにした
- 回数制限のファイルは cookie を取り直せばいくらでも増やせるので、数える期間を過ぎたもの（120秒より前）をこまめに消すようにした
- 壊れた deck.json を読むと PHP がエラーになっていた → 資料が無いものとして 404 にした
- GitHub Actions をタグではなくコミットのハッシュで指定した（タグを付け替えられても別のコードが動かない）
- 過去のコミットに自分のサーバーの情報が残っていたので、公開するリポジトリは1コミットにまとめた履歴で作り直した
  （それまでの private リポジトリは `slide-viewer-archive` に改名して残してある）
